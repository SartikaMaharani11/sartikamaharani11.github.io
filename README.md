# Ритм

Мобильное приложение задач на неделю. JavaScript + Vite, два адаптера хранения: локальный браузер и Supabase. Flat-интерфейс со светлой/тёмной темой и выбором акцента. Реализованы задачи, редактор, профиль и друзья.

## Запуск

Требуется Node.js 22+ и pnpm (либо npm).

```sh
pnpm install
pnpm dev
```

Открыть http://127.0.0.1:5173. Без `.env.local` приложение запускается с демоданными. Они сохраняются только в этом браузере, это НЕ Telegram-авторизация. При настроенном Supabase сначала показывается экран входа; демо остаётся отдельной кнопкой и никогда не загружается в облачную БД.

```sh
pnpm test
pnpm build
pnpm preview
```

## Что работает

- Две квадратные карточки: выполненные задачи и распределение по времени-сложности. Среднее = сумма сложностей / число задач; число повторений не влияет на вес.
- Четыре уровня; ультра-столбец скрыт при нуле, места остальных уровней сохраняются.
- Обычная задача — количество с целью 1, повторяемая — с любой целой целью до 999, процентная — до 100%. Нажатие добавляет 1 выполнение или 10 процентных пунктов. На максимуме не сбрасывается.
- Удержание строки 520 мс или кнопка карандаша открывают нижний редактор. Там доступны точные значения, смена типа, сложности, названия и удаление с повторным нажатием.
- Фильтры: все, в процессе, готово. Пустые состояния, клавиатура, фокус в модальном редакторе, уменьшение анимаций по системной настройке.
- Профиль: фото и username из Telegram, изменение отображаемого имени, шесть акцентных цветов и произвольный цвет, светлая/тёмная тема, выход. Имя и акцент сохраняются в `profiles` Supabase (в демо — отдельно локально), тема — на устройстве. Новая миграция для этого не требуется.
- Снизу на телефонах и планшетах — вкладки «Друзья», «Задачи», «Профиль»; от 900 px они переходят в боковую панель. Фото поддерживает `picture`, `avatar_url`, `photo_url`; при отсутствии/ошибке ссылки показываются инициалы и подсказка о повторном входе с разрешением `profile`.
- Друзья: все участники (свой профиль отмечен «Ты»), фото, имя, недельный счёт m/n и до трёх незавершённых задач с наибольшей долей выполнения. Участники без задач и завершившие всё тоже отображаются. Ниже — общее распределение сложности. Обновление при открытии вкладки, возвращении в приложение, каждые 30 секунд видимости вкладки и вручную; без настройки Realtime.
- В демо есть три вымышленных участника. При реальном входе используются только пользователи и задачи из Supabase. Список загружается постранично, чтобы не обрезаться стандартным лимитом API.
- Неделя с понедельника 00:00 по Москве для всех участников. Незавершённые задачи переходят с текущим прогрессом, завершённые остаются в истории. Повторения — цель внутри недели, автоматическое создание завершённой задачи каждую новую неделю пока не предусмотрено.

## Подключение БД и Telegram

Подробная инструкция: [docs/SETUP.md](docs/SETUP.md). Схема: [supabase/migrations/202611090001_initial.sql](supabase/migrations/202611090001_initial.sql).

Секреты Telegram хранит Supabase Auth. Клиент использует PKCE и стандартную сессию Supabase; подпись Telegram и обмен кодов проверяет сервер Supabase. Все вошедшие пользователи могут читать профили и задачи друг друга. Изменять задачи можно только свои и только текущей недели; это обеспечено RLS, а не фильтром интерфейса. Профиль использует существующие `display_name`, Telegram username/avatar и `accent_color`.

Перенос выполняется при открытии приложения/смене недели, без обязательного cron; операция на сервере идемпотентна и сериализована для одного пользователя. История хранится отдельными экземплярами задач, цепочка `rolled_from` предотвращает повторный перенос. Для друзей незавершённые задачи прошлых недель проецируются на текущую без записи чужих данных: прогресс виден до первого входа владельца на новой неделе. Удалённые экземпляры блокируют повторное появление предшественников. Новая миграция не требуется: существующие RLS-политики уже разрешают чтение всем вошедшим.

## GitHub Pages

Сборка — полностью статическая папка `dist`; секретов и собственного Node-сервера на хостинге нет. Vite использует относительные пути, сайт работает и в корне, и в `/repository/`. Workflow `.github/workflows/pages.yml` проверяет и публикует сайт при push в main или ручном запуске. Настройка GitHub, Supabase и BotFather: [docs/GITHUB_PAGES.md](docs/GITHUB_PAGES.md). Публичные параметры берутся из repository Actions variables, `.env.local` не загружается.

## Android

Этот же `dist` можно обернуть Capacitor. Подготовлен `capacitor.config.json`; APK сейчас не собирается. Перед сборкой нужны Android Studio/JDK и настройка системного браузера + deep link для OAuth — нельзя просто запускать Telegram popup внутри WebView. План: [docs/ANDROID.md](docs/ANDROID.md).

## Ограничения проверки

Доменная логика проверяется `pnpm test`. Без реквизитов проекта нельзя выполнить реальный Telegram OAuth и проверить миграцию на живом Supabase; сценарии проверки прав перечислены в инструкции. Локальное хранение — демо, не общая БД и не защищённый аккаунт. Сетевые ошибки показываются пользователю, не маскируются демоданными.
